# Touchspace AI package v1

The authoritative product brief is `app-spec.md`. The product is **Touchspace AI**; the backend module and routes use the `touchspace` namespace.

A `.touchspacemap` is a ZIP with exactly `manifest.json`, `geometry.json`, `landmarks.json`, `navigation.json`, and, for a live-capable scan, `worldmap.archive`. No paths, links, encrypted entries, duplicate names, or extra entries are permitted. Compressed and expanded size are limited to 64 MiB; individual JSON documents to 8 MiB. ZIP stored and DEFLATE entries are supported. Files are read in memory, never extracted to supplied paths. The Python server uses ZIP CRC verification; the Swift library checks entry bounds, CRC, and expansion size.

See `sample-data/touchspace-demo/` for canonical JSON and `backend/app/touchspace/models.py` for validation models (also exposed in OpenAPI). IDs are stable strings of 1–80 ASCII letters, digits, hyphens, or underscores. All documents carry the same `coordinateFrameId` UUID. Units are meters. Coordinates use ARKit's **X/Z horizontal plane** with Y up. Heading is radians: zero faces -Z, positive turns toward +X. Directions describe **phone-facing**, not body-facing direction. `spatial-test-vectors.json` is consumed by both Python and Swift tests.

The root `geometry.transform` is a column-major identity 4×4 matrix in v1: normalized geometry is already expressed in the saved session frame. Raw RoomPlan JSON, including original surface/object transforms, is retained as `capturedRoom`. Rooms specify surveyed polygons; absent areas are unknown. Walls are segments with doorway gaps cut explicitly. Objects are obstacle polygons. Clearance is at least 0.25 m. Navigation nodes and edges must lie in surveyed space and clear all recorded walls and obstacles. Cross-room edges require a matching explicit doorway. A doorway only participates in routing after a volunteer marks `traversable=true`; this is a scan-time label, not a claim about current accessibility or whether a door is open.

Disconnected graphs are retained with warnings and deterministic searches reject unreachable destinations. A landmark can lack a route node: its location remains inspectable but routing is unavailable. Its optional `nodeId` is a nearby surveyed destination waypoint, not a promise of contact with the object. A* uses Euclidean costs and heuristic. Collinear waypoint runs are simplified without moving points or cutting corners; doorway transition endpoints are retained and source node IDs remain complete. Live starts connect only to a visible graph node within 1.5 m; no wall-crossing snaps are allowed.

For real scans, add an `ARAnchor` at the session origin with name `touchspace-frame:<lowercase coordinateFrameId>` **before** capturing the world map. Store its identifier in `manifest.frameAnchorId`. RoomPlan and world-map capture must share the same `ARSession`. Only serialize a world map when mapping is `.mapped` or `.extending`. Serialize via `NSKeyedArchiver` with `requiringSecureCoding=true`. Import securely decodes `ARWorldMap`, checks its features and the saved frame anchor's ID, name, and identity transform. The server can only inspect keyed-archive structure; `worldDataStatus=present-unverified` never certifies that another device can restore it.

On restore, run `ARWorldTrackingConfiguration.initialWorldMap`. Live position is usable only when camera tracking is normal **and** the expected anchor is recovered in that frame. Insufficient horizontal camera direction, a position outside surveyed rooms, interruption, stale frames, or limited/lost tracking removes live pose and halts guidance. Recovery never automatically resumes a paused route. A 45-second relocalization timeout offers retry or map-only exploration. There is no manual location or heading entry.

Drafts may omit world data (`worldMapIncluded=false`). The bundled demo is synthetic and map-only. It deliberately includes a reachable exit and a disconnected store room. No synthetic ARWorldMap is shipped. Only a real device can validate scan/export/restore between installs or devices.
